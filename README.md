# TUR (Taiwan Ultra Runners) 路跑晶片計時平台（v3.12.3 完整建置與操作手冊）

本系統為 **TUR (Taiwan Ultra Runners)** 舉辦路跑與超級馬拉松活動專屬之免編譯網頁應用程式（PWA），整合：

- **Web NFC 共用晶片讀寫與 UID 雙模綁定**
- **選手現場報到感應 (`CHECKIN`) 與統一律定起跑計時**
- **一般距離賽（含分段配速／ETA）與繞圈計時賽（6H / 12H / 24H）**
- **多管理者獨立活動隔離與已結束活動鎖定歸檔**
- **歷年活動成績匯入、個人跨場次合併查詢與 ⚔️ 八百壯士英雄榜**
- **🏅 DUV 國際超馬協會官方格式成績匯出（`.xlsx` / `.csv`）**
- **🏅 官方中英對照＆客製化完賽證書製作／列印（PNG / 單張 PDF / 批次多頁 PDF，100% 離線生成）**
- **本機 IndexedDB 離線計時 ＋ Google 試算表雙向雲端同步**

> **介面設計原則**：大廳與作業畫面已全面極簡化（僅留頂部小 LOGO 與必要操作）；所有詳細規則、欄位格式、DUV 規範、證書製作與建置步驟，均集中收錄於本手冊。

## 一、系統核心功能與計時規則

| 核心功能 | 詳細規則與說明 |
|---|---|
| **跨場次共用 NFC 晶片** | 晶片僅寫入 `姓名\|身份證字號`（約 20 bytes），不含活動代碼或參賽編號。發卡一次即可重複參加多場不同賽事與組別，感應時依鎖定活動自動比對選手明細。 |
| **一般距離賽 / 繞圈計時賽** | 1. **🏃 一般距離賽**（42K / 50K / 100K 等）：依完賽時間排名，支援中途補給站分段時間、配速與 ETA。<br>2. **🔁 繞圈計時賽**（6H / 12H / 24H）：依單圈公里數（如 `2.54 km`）累積圈數與總里程排名，逾時圈次留存紀錄但不計入正式成績。 |
| **統一律定起跑時間** | 後台統一設定起跑時間（一鍵立即鳴槍或指定 `HH:mm:ss` 套用全組，亦可單組微調），不設起點感應門，簡化賽道設備。 |
| **選手報到感應 (`CHECKIN`)** | 賽前由報到組（`checkin01`）刷晶片登記到場，距離賽與繞圈賽皆適用，且**報到紀錄絕不計入圈數或賽道成績**。 |
| **多管理者活動隔離** | 支援建立多位活動管理員，每位管理員登入後**僅檢視與操作本人建立之活動、證書與名下作業員**，防止誤改他人賽事。 |
| **已結束活動鎖定與歸檔** | 活動改為「**已結束**」後，自動從大廳、作業員登入、後台其他分頁及公開頁「即時賽事」下拉選單隱藏防誤改；後台可點「**🔓 重新開啟**」恢復，公開端則自動歸檔至「**📜 歷年成績**」與「**🏅 證書列印**」。 |
| **刪除活動連動清理** | 刪除活動時同步永久清除本機與雲端該活動的報名明細（`Registrations`）與感應紀錄（`Scans`）並收縮試算表，共用晶片主檔（`Chips`）保留不受影響。 |
| **歷年匯入與 ⚔️ 八百壯士專區** | 後台「**📜 歷年匯入**」支援匯入過往成績並與本系統個人紀錄以身份證合併；凡活動名稱含「**八百壯士**」（進行中、已結束或歷年匯入）自動整合至「**⚔️ 八百壯士**」當年度整合排名與跨年度英雄榜。 |
| **🏅 DUV 官方成績匯出** | 一鍵匯出符合 **DUV (Deutsche Ultramarathon-Vereinigung)** 送審格式（3 列活動表頭＋11 欄完賽明細）之 `.xlsx`（同表堆疊／分組工作表）與 `.csv`（UTF-8 BOM）；支援自動拆中文姓／名與依身份證第 2 碼推算性別。 |
| **🏅 完賽證書製作與客製化** | • **活動範圍限制**：後台「**🏅 製作證書**」與公開頁「**🏅 證書列印**」皆**僅包含「已結束」與「歷年」活動**（進行中與籌備中賽事不列入）。<br>• **後台製作證書**：活動管理員可針對已結束或歷年活動產出「**🏛️ 官方中英文對照公版**（含大字活動名、分段成績、活動日期、金色鋼印與下方 TUR LOGO）」或「**🖼️ 上傳自訂底圖套印**（畫布拖曳微調）」，支援 PNG、單張 PDF 與**批次多頁合併 PDF**。<br>• **公開頁證書列印**：選手免登入即可下載官方樣式證書，或使用「**✨ 客製化**」上傳**自訂底圖＋個人照片**整合下載 PNG／PDF／直接列印。<br>• **統一時間格式**：全系統所有成績與感應時間之秒數一律採整數 **`HH:mm:ss`** 顯示與匯出（不含小數點）。 |
| **離線作業＋雙向同步** | 有網自動雙向同步；山區無訊號可離線登入感應並存於本機 IndexedDB，連網後一鍵補傳或匯出 JSON 合併。PDF 與證書渲染亦 100% 離線運作。 |
| **個資隱碼保護** | 公開查詢頁與隱碼 Excel 全面隱碼身份證（如 `A123****89`），並隱藏選手出生年月日（`DOB`）；查詢仍支援完整身份證以 SHA-256 雜湊安全比對。 |

### 選手狀態自動流轉規則

| 狀態 | 判定條件 |
|---|---|
| **⏳ 未報到** | 尚未感應 `CHECKIN` 報到晶片，且無任何賽道感應紀錄 |
| **✅ 已報到** | 已完成 `CHECKIN` 報到感應，等待到達統一律定起跑時間 |
| **🏃 賽道上** | 已報到且已達起跑時間，或已通過任一中途站／繞圈感應 |
| **🏁 已完賽** | 距離賽通過終點衝線門（`FINISH`）；繞圈賽達限時截止且有有效圈數 |

## 三、從零開始建置與版本升級步驟（約 10 分鐘完成）

### 步驟 1：建立 Google 試算表與部署後端 API

1. 建立一份新的 **Google 試算表**（例如「TUR 路跑晶片計時資料庫」）。
2. 點選上方「**擴充功能**」→「**Apps Script**」，清空預設內容，將 `gas/Code.gs` 完整貼上並儲存。
3. 上方函式選單選 **`setupSheets`** → 按「**執行**」（首次需授權「進階 → 前往 → 允許」），自動建立 **8 張工作表**：
   - `GlobalConfig`、`AdminAccounts`、`Events`（15 欄）、`StaffAccounts`、`Chips`、`Registrations`（14 欄，含 DUV 欄位）、`Scans`、`HistoryResults`（17 欄）。
4. 點右上角「**部署**」→「**新增部署作業**」：
   - 類型：**網頁應用程式** ｜ 執行身分：**我** ｜ 誰可以存取：**所有人 (Anyone)**
   - 複製產生的部署網址（`https://script.google.com/macros/s/....../exec`）。

> **舊版升級提醒（v3.9 以下升至 v3.10+）**：
> 貼上最新 `gas/Code.gs` 後，請點「**部署 → 管理部署作業 → 鉛筆圖示 → 版本選『建立新版本』→ 部署**」（原網址不變）。既有 `Events` 與 `Registrations` 工作表會自動補齊新增的 DUV 欄位標題，並修正時間格式與重複 ID 匯入問題，不影響舊資料。

### 步驟 2：填入共用雲端網址

開啟 `js/config.js`，將部署網址填入 `DEFAULT_GAS_URL`：
```javascript
window.APP_CONFIG = {
  DEFAULT_GAS_URL: 'https://script.google.com/macros/s/貼上您的部署網址/exec',
  AUTO_SYNC_ON_START: true
};
```

### 步驟 3：上傳至 GitHub 並啟用 HTTPS（Web NFC 必備）

> Android Chrome 的 Web NFC API **強制要求 HTTPS**，直接雙擊本機檔案無法使用實體 NFC。

1. 在 GitHub 建立公開（Public）儲存庫，上傳整個專案（務必保留 `css/`、`js/` 子資料夾，且包含新增的 `js/certificate.js`）。
2. 進入 **Settings → Pages**：Source 選 **Deploy from a branch**、Branch 選 `main`、資料夾選 `/ (root)` → 按 **Save**。
3. 啟用後即可透過 HTTPS 使用：
   - **系統主入口**：`https://<您的帳號>.github.io/<儲存庫名稱>/`
   - **公開查詢頁**：`https://<您的帳號>.github.io/<儲存庫名稱>/public.html`

### 5.2 公開查詢頁 4 大模式 (`public.html`)

頁面頂部提供 4 大模式切換頁籤，且每 20 秒自動刷新（處於「🏅 證書列印」時不中斷選手編輯與拖曳）：

| 模式頁籤 | 核心功能與操作方式 |
|---|---|
| **🏃 即時賽事** | • 僅顯示進行中／籌備中活動（已結束活動自動隱藏）。<br>• 輸入姓名、編號或完整身份證查詢即時報到、分段／逐圈明細與 ETA。<br>• 顯示 5 張 KPI 數據卡、分組進度、站點通過（或繞圈 TOP 6）與各組排行榜（點擊選手列可快速展開明細）。 |

## 六、完整賽事標準作業流程（SOP）

1. **階段 1（賽前後台建置）**：登入管理者 → 建立活動（填妥中文與英文活動名稱）→ 設定分組與站點 → 匯入名單（含選填 DUV 欄位：性別、DOB、城市、國家）→ 設定各站作業員 → 雙向同步並張貼公開查詢 QR Code。
2. **階段 2（選手發卡製卡 `writer01`）**：Android Chrome 登入 `writer01` → 帶入選手 → NTAG 寫入＋回讀驗證（或唯讀卡綁定 UID）；已持共用晶片者免重發。
3. **階段 3（現場報到感應 `checkin01`）**：選取活動登入 `checkin01` → 刷晶片登記報到，未帶卡可手動補登或後台補報到。
4. **階段 4（統一鳴槍與賽道感應）**：後台點擊「🔫 立即鳴槍」→ 各站感應（無訊號離線暫存，連網按「☁️ 上傳」）。
5. **階段 5（成績核對與 DUV 送審）**：
   - 於「**🏆 成績**」核對並人工修正異常紀錄（全系統時間統一無小數秒 `HH:mm:ss`）。
   - 下載完整版／隱碼公開版 Excel 與 **🏅 DUV 官方成績檔**（`.xlsx` / `.csv`）提交 DUV 認證。
6. **階段 6（賽後鎖定歸檔與證書核發）**：
   - 活動狀態改為「**已結束**」即鎖定防誤改，並自動開放於後台「**🏅 製作證書**」與公開頁「**📜 歷年成績**」、「**🏅 證書列印**」。
   - 主辦可於後台批次產製全組 PDF，選手亦可免登入下載官方／客製化個人照片證書；日後需釋放空間再點「刪除」連動清理明細。

## 七、Android 硬體事前設定與常見問題排錯

### 1. Android 手機事前設定清單

| 檢查項目 | 注意事項 |
|---|---|
| **支援瀏覽器** | Web NFC **僅支援 Android Google Chrome（v89 以上）**；不支援 iOS Safari、電腦瀏覽器，也**不可在 LINE / FB 內建瀏覽器開啟**。 |
| **建議 NFC 晶片** | 建議 **NTAG213 / 215 / 216** 抗金屬貼紙或手環；唯讀／MIFARE 卡改用「**🔗 綁定 UID**」。 |
| **手機設定** | 開啟 **NFC**、開啟「**自動設定日期與時間（網路校時）**」、延長螢幕休眠並外接行動電源。 |
| **安裝 PWA** | Chrome 選單點「**加到主畫面**」全螢幕運行。 |
| **防連點秒數** | 距離賽建議 `30 秒`；繞圈賽建議 `60～120 秒`。 |

### 2. 常見異常排錯速查表

| 狀況 / 錯誤訊息 | 原因 | 解決方法 |
|---|---|---|
| `NotAllowedError` | Chrome 未允許 NFC 權限或手機 NFC 未開 | 點網址列左側圖示 → 權限 → 允許「NFC 裝置」，並確認手機已開啟 NFC。 |
| `NotSupportedError` | 晶片為 MIFARE Classic 或唯讀卡 | 改點「**🔗 綁定 UID**」直接綁定，或更換 NTAG 晶片。 |
| `NetworkError` | 晶片移開太快或未對準天線 | 貼緊手機背面天線並**靜止 1～2 秒**，聽到成功音效再移開。 |
| 雲端歷年時間變成 1899 年日期或無法寫入 DUV 欄位 | 雲端 GAS 仍停留在舊版（v3.9 以下） | 貼上最新 `gas/Code.gs`（v3.10+）並點「管理部署作業 → 建立新版本 → 部署」。 |
| 下拉選單找不到某活動 | 活動狀態已設為「**已結束**」並鎖定 | 至後台「**🏟️ 活動**」點該活動之「**🔓 重新開啟**」。 |
| 看不到其他管理員的活動 | 系統啟用**多管理者活動隔離** | 屬正常設計；民眾請由公開查詢頁瀏覽所有活動。 |
| 更新 GitHub 後手機仍是舊版 | Service Worker 尚留舊版離線快取 | 於手機 Chrome **連續重新整理 2 次**即可更新至 `v3.12.3`。 |
