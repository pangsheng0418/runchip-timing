# TUR (Taiwan Ultra Runners) 路跑晶片計時平台（v3.10 完整建置與操作手冊）

本系統為 **TUR (Taiwan Ultra Runners)** 舉辦路跑與超級馬拉松活動專屬之免編譯網頁應用程式（PWA），整合 **Web NFC 共用晶片讀寫**、**選手報到感應**、**多管理者活動隔離**、**歷年活動成績匯入與個人合併查詢**、**⚔️ 八百壯士歷年英雄榜與當年度成績整合**、**🏅 DUV 國際超馬協會官方格式成績匯出**、**本機 IndexedDB 離線計時** 與 **Google 試算表雲端同步**。

> **介面設計原則**：系統畫面已全面簡化，僅保留必要資訊與直覺操作按鈕；所有詳細功能定義、匯入欄位範例、八百壯士系統整合規則與操作方法，均集中收錄於本手冊。

## 一、系統核心功能與計時規則

| 核心特色 | 詳細規則與說明 |
|---|---|
| **跨場次共用 NFC 晶片** | 晶片僅寫入 `姓名\|身份證字號`（約 20 bytes），不含活動代碼或參賽編號。每位選手發卡一次即可重複參加本平台不同場次與組別，感應時系統依「目前鎖定活動」自動以身份證字號（或晶片 UID）比對參賽明細。 |
| **支援兩種活動性質** | 1. **🏃 一般距離賽**：如 42K / 21K / 10K，依「完賽時間」排名，支援中途補給站分段配速與預估完賽時間（ETA）。<br>2. **🔁 繞圈計時賽**：如 6H / 12H / 24H，無中途管制點，依設定之「每圈公里數（如 `2.54 km`）」累積總圈數與總里程排名，逾時圈次留存紀錄但不計入正式成績。 |
| **統一律定起跑時間** | 各活動於後台統一設定「**律定起跑時間**」（支援現場一鍵鳴槍或指定 `HH:mm:ss` 套用全組，亦可於分組內「個別微調」）。不設起點感應門，不另計算個人淨時間，簡化設備與現場作業。 |
| **選手報到感應 (`CHECKIN`)** | 賽前由報到組（`checkin01`）刷晶片即時登記到場，掌握已報到／未報到人數。距離賽與繞圈賽皆適用，且**報到紀錄絕不計入繞圈圈數或賽道成績**。 |
| **多管理者活動隔離** | 平台可建立多位主辦／活動管理者帳號；每位管理者登入後**僅檢視與管理本人建立的活動與名下作業員**，防止誤改他人賽事資料。 |
| **已結束活動鎖定與歷年歸檔** | 活動狀態設為「**已結束**」後，自動從大廳、作業員登入、後台活動切換、晶片寫入篩選、作業員限定活動選單，以及**公開查詢頁「即時賽事」下拉選單**隱藏，且禁止作業員登入感應與後台修改；後台僅保留於「活動」分頁清單（可點「**🔓 重新開啟**」恢復），公開端則自動歸檔至「**📜 歷年成績**」供查詢個人歷年成績。 |
| **刪除活動連動清理資料庫** | 刪除活動時，同步永久清除本機 IndexedDB 與雲端試算表該活動所有報名明細（`Registrations`）與感應紀錄（`Scans`），並自動收縮試算表空白列；跨活動共用晶片主檔（`Chips`）不受影響。 |
| **歷年活動成績匯入與個人合併** | 後台「**📜 歷年匯入**」支援上傳 Excel（`.xlsx`）／CSV 或貼上文字匯入以前歷年活動與成績（附一鍵下載範本），並與系統內「已結束活動」自動以身份證字號（或同姓名唯一比對）合併，供選手於公開查詢頁一次查閱歷年全部成績。 |
| **⚔️ 八百壯士系統專屬英雄榜與年度整合** | 凡活動名稱包含「**八百壯士**」（不論進行中、已結束或歷年匯入），系統自動歸入「**⚔️ 八百壯士**」獨立專區，提供「**當年度成績整合資訊**（年度場次、參賽／完賽人次、年度總里程與個人年度整合排名）」與「**歷年英雄榜**（跨年度累計里程總排名與個人歷屆明細）」。 |
| **🏅 DUV 國際超馬協會成績匯出** | 支援一鍵匯出符合 **DUV (Deutsche Ultramarathon-Vereinigung)** 官方送審格式（3 列活動表頭＋11 欄完賽明細）之 `.xlsx`（同工作表堆疊／分組工作表）與 `.csv`（UTF-8）報表；中文自動拆姓／名、性別可由台灣身份證第 2 碼自動推算，並支援繞圈計時賽輸出總里程 `km` 或累積時間。 |
| **離線作業＋雙向自動同步** | 有網路時開機自動雙向同步雲端；無訊號山區可離線登入與感應並暫存本機 IndexedDB，恢復連線後按「**☁️ 上傳**」批次補傳，或匯出 `.json` 離線備份檔由總部合併。 |
| **個資隱碼保護** | 公開查詢頁與隱碼版 Excel 全面將身份證字號隱碼（如 `A123****89`），查詢時仍可輸入完整身份證字號以 SHA-256 雜湊安全比對。 |

### 選手狀態自動流轉規則

| 狀態 | 判定條件 |
|---|---|
| **⏳ 未報到** | 尚未感應 `CHECKIN` 報到晶片，且無任何賽道感應紀錄 |
| **✅ 已報到** | 已完成 `CHECKIN` 報到感應，等待到達統一律定起跑時間 |
| **🏃 賽道上** | 已報到且已達統一律定起跑時間，或已通過任一中途站／繞圈感應 |
| **🏁 已完賽** | 距離賽通過終點衝線門（`FINISH`）；繞圈賽達限時截止且有有效圈數 |

## 三、第一次使用者：從零開始建置步驟（約 10 分鐘完成）

### 步驟 1：建立 Google 試算表與部署後端 API

1. 登入 Google 雲端硬碟，建立一份全新的 **Google 試算表**（例如命名為「智慧路跑計時資料庫」）。
2. 點選上方選單「**擴充功能**」→「**Apps Script**」。
3. 將編輯器內原有文字清空，把本專案 `gas/Code.gs` 內容**完整複製貼上**並按 `Ctrl+S` 儲存。
4. 在上方函式下拉選單選擇 **`setupSheets`** → 點擊「**執行**」：
   - 首次執行請點「**審查權限**」→ 選取帳號 →「**進階**」→「**前往（不安全）**」→「**允許**」。
   - 執行完成後會自動建立 **8 張工作表**：`GlobalConfig`、`AdminAccounts`、`Events`、`StaffAccounts`、`Chips`、`Registrations`、`Scans`、`HistoryResults`。
5. 點選右上角「**部署**」→「**新增部署作業**」：
   - 類型：**網頁應用程式**
   - 執行身分：**我**
   - 誰可以存取：**所有人 (Anyone)**
   - 點擊「**部署**」，複製產生的 **網頁應用程式網址**（`https://script.google.com/macros/s/....../exec`）。

> **舊版升級提醒**：若先前已部署舊版 `Code.gs`，更新程式碼後請點「**部署 → 管理部署作業 → 鉛筆圖示 → 版本選『建立新版本』→ 部署**」（原網址不變）。

### 步驟 2：填入共用雲端網址（全裝置免手動設定）

1. 開啟 `js/config.js`，將步驟 1 複製的網址貼入 `DEFAULT_GAS_URL` 引號內並存檔：
   ```javascript
   window.APP_CONFIG = {
     DEFAULT_GAS_URL: 'https://script.google.com/macros/s/貼上您的部署網址/exec',
     AUTO_SYNC_ON_START: true
   };
   ```
2. 設定完成後，所有電腦與手機一開啟網頁且有網路時，會自動與同一份 Google 試算表雙向同步。

### 步驟 3：上傳至 GitHub 並啟用 HTTPS（Web NFC 必備）

> Android Chrome 的 Web NFC API **強制要求 HTTPS 安全連線**，直接雙擊本機 `index.html` 無法使用實體 NFC。

1. 在 GitHub 建立一個公開（Public）儲存庫。
2. 將整個專案資料夾內的檔案（保留 `css/`、`js/` 子資料夾及填好網址的 `js/config.js`）上傳至 `main` 分支。
3. 進入儲存庫 **Settings → Pages**：
   - Source 選 **Deploy from a branch**
   - Branch 選 `main`、資料夾選 `/ (root)` → 按 **Save**。
4. 等待約 1～2 分鐘即可透過 HTTPS 網址使用：
   - **系統入口大廳**：`https://<您的帳號>.github.io/<儲存庫名稱>/`
   - **公開即時查詢頁**：`https://<您的帳號>.github.io/<儲存庫名稱>/public.html`

| **進階同步工具**（折疊區） | <ul><li>**⬇️ 僅拉取雲端**：單向從雲端下載覆蓋本機快取。</li><li>**📤 強制推送設定**：強制將本機活動、分組、站點與帳號設定推送至雲端。</li><li>**📋 複製 config.js**：產生 `js/config.js` 程式碼供貼入 GitHub 儲存庫。</li></ul> |
| **🧪 測試資料與重置**（折疊區・僅最高管理員） | <ul><li>**⚡ 載入模擬資料**：一鍵建立 3 場示範活動（含距離賽與 2.54km 繞圈計時賽）。</li><li>**🗑️ 清空本機資料**：清除本機 IndexedDB 所有資料並重設預設帳密。</li></ul> |

## 六、完整賽事標準作業流程（SOP）

### 階段 1：賽前後台建置

1. 以負責該賽事的管理者帳號登入後台（首次可用最高管理員 `admin / admin1234` 登入，並於「**🏟️ 活動 → 👥 平台管理者帳號**」視需要建立多位活動管理者）。
2. 點擊「**＋ 新增活動**」，選擇「一般距離賽」或「繞圈計時賽」並建立活動。
3. 切換至「**⏱️ 起跑與站點**」確認分組與站點設定（距離賽不需設起點門；繞圈賽確認每圈公里數）。
4. 切換至「**👥 名單**」，點擊「**📤 匯入 Excel / CSV**」匯入 4 欄格式名單：
   ```csv
   參賽編號,姓名,身份證字號,分組代碼
   A001,林志明,A123456789,42K
   U001,林志明,A123456789,12H
   ```
5. 切換至「**👷 作業員**」確認或新增本場各站作業員帳密。
6. 切換至「**☁️ 匯出與同步**」點擊「**🔄 雙向同步**」，並複製「**🌐 公開查詢連結**」製成 QR Code 張貼會場。

### 階段 2：選手發卡製卡（`writer01`）

> 若選手已持有本平台發放之共用晶片，可**直接跳過本階段**前往階段 3 報到感應。

1. 使用 Android Chrome 開啟系統 →「**晶片作業**」→ 以 `writer01` 登入。
2. 於右側「選手清單」點擊「**帶入寫卡**」（或手動輸入姓名與身份證）。
3. NTAG 可寫入晶片點「**📡 寫入晶片**」並於寫入後點「**🔍 回讀驗證**」；唯讀／MIFARE 卡改點「**🔗 綁定 UID**」。

### 階段 3：賽前現場報到感應（`checkin01`）

1. 報到人員選取本次活動並以 `checkin01` 登入（自動鎖定 `CHECKIN` 報到區）。
2. 點擊「**📡 啟動 NFC 感應**」，選手刷晶片即顯示綠閃「報到成功」與即時報到進度（`已報到 X / Y`）；未帶晶片者可使用「**⌨️ 手動補登**」或由後台「名單」點「**+ 補報到**」。

### 階段 4：統一鳴槍起跑與賽道感應

1. 主辦於後台「**⏱️ 起跑與站點**」點擊「**🔫 立即鳴槍**」（或輸入時間按「**套用全組**」）。
2. 各站作業員先於有訊號處選取活動並登入專屬帳號（如 `lap01`、`cp1`、`cp2`、`finish01`），系統會自動快取最新名單與晶片主檔。
3. 點擊「**📡 啟動 NFC 感應**」（建議開啟「🔊 音效」與「☀️ 高對比」）。若遇無網路區域，資料安全暫存本機，連網後按「**☁️ 上傳**」批次補傳。

### 階段 5：成績核對與匯出

1. 主辦於後台「**🏆 成績**」檢視排名，點擊任何時間或罰時即可人工補登修正（繞圈賽點「逐圈明細 / 補刪圈」）。
2. 切換至「**☁️ 匯出與同步**」下載「**📥 完整版**」與「**📥 隱碼公開版**」Excel 報表，並下載「**⬇️ 下載備份**」留存 JSON 備份。

### 階段 6：賽後鎖定與清理

1. **鎖定保護與歸檔**：至「**🏟️ 活動 → ✏️ 活動基本設定**」將狀態改為「**已結束**」並儲存。該活動將自後台管理、作業員感應及公開頁「即時賽事」下拉選單隱藏防誤改，並自動歸檔至公開頁「**📜 歷年成績**」供選手查詢歷年紀錄。
2. **清理舊資料**：日後若需釋放資料庫空間，於「**🏟️ 我的活動**」點擊「**刪除**」，即可同步永久清除本機與雲端該活動之報名與感應明細（保留選手共用晶片主檔）。

## 七、硬體事前設定與常見問題排錯

### 1. Android 手機事前設定清單

| 檢查項目 | 注意事項 |
|---|---|
| **支援裝置與瀏覽器** | Web NFC **僅支援 Android 手機之 Google Chrome（v89 以上）**。<br>❌ 不支援 iPhone (iOS Safari)、電腦瀏覽器，也**不可在 LINE / Facebook 內建瀏覽器開啟**（請選「以 Chrome 開啟」）。 |
| **建議採購 NFC 晶片** | 建議採購 **NTAG213 / NTAG215 / NTAG216** 抗金屬貼紙或矽膠手環。若使用唯讀卡或 MIFARE 卡，請改用「**🔗 綁定 UID**」。 |
| **Android 系統設定** | 1. 開啟手機「設定 → 連線裝置 → **NFC**」。<br>2. 開啟「**自動設定日期與時間（網路校時）**」，確保各站時間一致。<br>3. 延長螢幕休眠並外接行動電源。 |
| **建議安裝為 PWA** | 於 Chrome 選單點「**加到主畫面**」全螢幕運行，避免單手操作誤觸返回鍵。 |
| **防連點秒數建議** | 一般距離賽預設 `30 秒`；繞圈計時賽（例如單圈 2.54 km）建議調高至 `60～120 秒`，避免補給停留重複刷卡。 |

### 2. 常見異常排錯速查表

| 狀況 / 錯誤訊息 | 原因 | 解決方法 |
|---|---|---|
| `NotAllowedError` | Chrome 未允許 NFC 權限或手機 NFC 未開 | 點網址列左側圖示 → 權限 → 允許「NFC 裝置」，並確認手機 NFC 已開啟。 |
| `NotSupportedError` | 晶片為 MIFARE Classic、悠遊卡或唯讀卡 | 改點「**🔗 綁定 UID**」免寫入直接綁定，或更換 NTAG213/215/216 晶片。 |
| `NetworkError` | 感應時晶片移開太快或距離天線太遠 | 貼緊手機背面 NFC 天線並**靜止 1～2 秒**，聽到成功音效後再移開。 |
| 新建活動管理者無法雲端登入 | Google Apps Script 未更新部署至 v3.5+ | 將最新 `gas/Code.gs` 貼入 Apps Script，點「部署 → 管理部署作業 → 建立新版本 → 部署」。 |
| 刪除活動後雲端試算表仍有舊明細 | 雲端 GAS 仍停留在舊版 | 重新貼上新版 `gas/Code.gs`（v3.5+）並建立新版本部署。 |
| 下拉選單或其他分頁找不到某活動 | 活動狀態已設為「**已結束**」並鎖定 | 至後台「**🏟️ 活動**」清單點該活動的「**🔓 重新開啟**」。 |
| 看不到其他管理者建立的活動 | 系統啟用**多管理者活動隔離** | 屬正常設計（每位管理者僅管理本人活動）；民眾請由公開查詢頁檢視所有活動。 |
| 更新 GitHub 後手機仍是舊畫面 | Service Worker 仍保留舊版離線快取 | 於手機 Chrome **連續重新整理 2 次**，或關閉分頁重開即可更新。 |

## 八、免硬體快速體驗方式（電腦／手機皆可）

1. 以最高管理員（`admin / admin1234`）登入後台 →「**☁️ 匯出與同步**」→ 展開「**🧪 測試資料與重置**」→ 點「**⚡ 載入模擬資料**」。
2. 系統自動建立 3 場示範活動（含距離賽與 2.54 km 繞圈計時賽、報到與未報到選手資料）。
3. 接著可快速體驗：
   - **多管理者隔離**：於「**🏟️ 活動**」展開「**👥 平台管理者帳號**」新增 `admin2`，登出後改用 `admin2` 登入驗證活動隔離。
   - **報到與名單篩選**：於「**👥 名單**」篩選未報到選手並點擊「**+ 補報到**」。
   - **模擬刷卡感應**：登出後進入「**晶片作業**」，展開「**測試帳號快選**」選擇 `checkin01`、`lap01`、`cp1` 或 `finish01` 登入，展開「**🧪 模擬感應測試**」體驗刷卡比對與攔截。
   - **公開查詢頁**：開啟 `public.html` 切換 3 場活動查看即時排行榜與選手動態。
