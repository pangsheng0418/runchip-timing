# 智慧路跑 NFC 多場次共用晶片計時平台（v3.3 完整建置與操作手冊）

本系統為免編譯之網頁應用程式（PWA），整合 **Web NFC 晶片讀寫**、**本地 IndexedDB 離線計時** 與 **Google 試算表雲端多機同步**。適合馬拉松、公益路跑與超馬繞圈計時賽使用。

---

## 一、系統核心功能總覽

| 核心特色 | 功能說明 |
|---|---|
| **多場次活動平台** | 同一系統可建立多場路跑活動，各場次獨立管理分組、鳴槍時間、站點、選手名單與成績查詢。 |
| **支援兩種活動性質** | 1. **🏃 一般距離路跑**（如 42K / 21K / 10K，依大會或淨時間排名，含各補給站分段配速與 ETA）。<br>2. **🔁 繞圈計時賽**（如 6H / 12H / 24H，無中間管制點，設定每圈公里數如 `2.54 km`，依累積總里程排名）。 |
| **跨場次共用 NFC 晶片** | 晶片僅寫入「**姓名｜身份證字號**」（約 20 bytes），選手發卡一次即可重複參加不同場次與不同組別，免重複寫卡。 |
| **三區權限嚴格管制** | 進入首頁即顯示「**公開查詢頁**（免登入）」、「**晶片計時作業**（帳密鎖定活動與站點防誤刷）」、「**後台管理區**（最高權限獨立帳密）」。 |
| **離線作業＋自動同步** | 有網路時開機自動雙向同步雲端；山區無訊號時可離線登入並感應暫存本機，連網後一鍵統一上傳（亦支援匯出離線 JSON 檔交由總部合併）。 |
| **個資隱碼與安全備份** | 公開查詢頁全面隱碼身份證字號（如 `A123****89`）；後台支援一鍵匯出 Excel（`.xlsx`）與完整系統 JSON 備份還原。 |

## 三、第一次使用者：從零開始建置步驟（約 10 分鐘完成）

### 步驟 1：建立 Google 試算表與部署後端 API

1. 登入 Google 雲端硬碟，建立一份全新的 **Google 試算表**（例如命名為「智慧路跑計時資料庫」）。
2. 點選上方選單「**擴充功能**」→「**Apps Script**」。
3. 將編輯器內原有文字清空，把本專案 `gas/Code.gs` 內容**完整複製貼上**並按 Ctrl+S 儲存。
4. 在工具列上方函式下拉選單選擇 **`setupSheets`** → 點擊「**執行**」：
   - 首次執行會跳出 Google 權限審查視窗，請點「**審查權限**」→ 選取您的帳號 → 點「**進階**」→「**前往（不安全）**」→「**允許**」。
   - 執行完成後，試算表會自動建立 6 張工作表：`GlobalConfig`、`Events`、`StaffAccounts`、`Chips`、`Registrations`、`Scans`。
5. 點選右上角「**部署**」→「**新增部署作業**」：
   - 點擊齒輪選類型：**網頁應用程式**
   - 執行身分：**我**
   - 誰可以存取：**所有人 (Anyone)**
   - 點擊「**部署**」。
6. **複製產生的「網頁應用程式網址」**（格式為 `https://script.google.com/macros/s/....../exec`）。

> **日後若更新 `Code.gs`**：請點「**部署 → 管理部署作業 → 右上角鉛筆圖示 → 版本選『建立新版本』→ 部署**」，網址維持不變即可生效。

---

### 步驟 2：填入共用雲端網址（讓全部手機自動同步！）

1. 用記事本或編輯器打開 `js/config.js`。
2. 將步驟 1 複製的網址貼入 `DEFAULT_GAS_URL` 引號內並存檔：
   ```javascript
   window.APP_CONFIG = {
     DEFAULT_GAS_URL: 'https://script.google.com/macros/s/貼上您的部署網址/exec',
     AUTO_SYNC_ON_START: true
   };
   ```
3. **為什麼要做這步？** 設定好之後，無論是主辦電腦、各站工作人員手機，還是民眾打開公開查詢頁，**只要有網路一進入頁面就會自動同步同一份 Google 試算表**，徹底杜絕各裝置資料不一致！

---

### 步驟 3：上傳至 GitHub 並開啟 HTTPS 網站（Web NFC 必備）

> Android Chrome 的 Web NFC API **強制要求 HTTPS 安全連線**，直接雙擊電腦裡的 `index.html` 無法使用實體 NFC。

1. 在 GitHub 建立一個新的公開（Public）儲存庫（Repository）。
2. 將整個專案資料夾內的檔案（包含 `css/`、`js/` 子資料夾及填好網址的 `js/config.js`）上傳至 `main` 分支。
3. 進入儲存庫上方 **Settings** → 左側 **Pages**：
   - Source 選 **Deploy from a branch**
   - Branch 選 `main`、資料夾選 `/ (root)` → 按 **Save**。
4. 等待約 1～2 分鐘，頁面會顯示您的專屬 HTTPS 網址：
   - **系統入口大廳**：`https://<您的帳號>.github.io/<儲存庫名稱>/`
   - **公開即時查詢頁**：`https://<您的帳號>.github.io/<儲存庫名稱>/public.html`

## 五、完整賽事操作流程（SOP）

### 階段 1：賽前後台建置（主辦管理員）

1. 進入「**🛡️ 後台管理區**」（預設 `admin / admin1234`）。
2. **建立路跑活動**：
   - 點擊右上角「**＋ 建立新路跑活動**」。
   - 選擇活動性質：
     - **🏃 一般距離路跑**：設定活動名稱、日期、地點；建立後於「**🔫 分組鳴槍與站點**」設定各組距離與站點累計距離（供計算分段配速與 ETA）。
     - **🔁 繞圈計時賽**：輸入**每圈設定公里數**（例如 `2.54`），系統自動建立 `6H / 12H / 24H` 三組與單一 `LAP` 感應區（無中間管制點）；可在「分組鳴槍」自由修改時數。
3. **事前匯入本活動選手名單與組別**：
   - 切換至「**👥 選手名單與組別匯入**」，確認上方「目前管理活動」正確。
   - 準備 Excel（`.xlsx`）或 CSV 檔案，欄位順序固定為 4 欄：
     ```
     參賽編號,姓名,身份證字號,分組代碼
     A001,林志明,A123456789,42K
     U001,林志明,A123456789,12H
     ```
   - 同一位選手（同身份證字號）可用不同參賽編號與組別匯入多場不同活動。
4. **管理作業人員帳號與修改管理員密碼**：
   - 於「**🏟️ 活動管理與帳密**」修改最高管理員帳密。
   - 於「**👷 作業員帳號管制**」調整各站帳密，並可設定帳號為「限定單一活動」或「適用所有活動（登入時由人員選取）」。
5. **執行雲端雙向同步**：
   - 於「**💾 備份匯出與雲端同步**」點「**🔄 一鍵完整雙向同步**」，將全部活動、名單與帳密同步上雲端。

---

### 階段 2：選手報到與共用 NFC 晶片寫入（報到人員 `writer01`）

1. 使用 **Android 手機 Chrome** 進入「**📡 晶片計時作業**」，以 `writer01` 登入。
2. 從右側名單點選「**帶入寫卡**」（或手動輸入**選手姓名**與**身份證字號**）。
3. **兩種製卡模式（依您採購的晶片種類選擇）**：
   - **標準可寫入晶片（NTAG213 / 215 / 216）**：
     1. 點擊「**📡 寫入共用 NFC 晶片**」。
     2. 將晶片緊貼手機背面 NFC 天線並**保持靜止 1～2 秒**，聽到成功音效即完成寫入 `姓名|身份證字號`。
     3. 建議移開晶片 1 秒後，點擊綠框內的「**🔍 點此回讀驗證晶片**」再貼近一次，確認資料無誤並記錄硬體 UID。
   - **唯讀晶片 / MIFARE Classic 卡（若寫入顯示 `NotSupportedError`）**：
     1. 改點「**🔗 僅綁定晶片 UID**」，貼近晶片 1 秒即完成免寫入綁定。
     2. 賽道感應端會自動透過晶片硬體 UID 反查該選手身份證並比對各場次明細，同樣可跨場次共用！
4. 可隨時點「**🔍 讀取 / 測試晶片**」檢查任意晶片內的資料與該選手已報名的所有活動場次。

---

### 階段 3：賽前準備與鳴槍起跑

1. **各站手機開機同步（有網路處）**：
   - 各站工作人員先在報到處（有網路環境）用手機開啟系統，選擇本次作業活動並登入自己的站點帳號（如 `lap01`、`start01`、`cp1`、`finish01`）。
   - 系統會自動把該活動所有選手名單、晶片主檔與帳密快取至手機離線資料庫。
2. **各分組鳴槍起跑**：
   - 裁判於後台「**🔫 分組鳴槍與站點**」點擊各組的「**🔫 一鍵鳴槍起跑**」（或手動輸入精準起跑時間 `HH:mm:ss`）。

---

### 階段 4：賽道晶片感應計時（有網即時 / 無網離線皆可）

1. 作業員登入後，系統會**鎖定本次活動與負責站點**，防止誤選站點或錯場。
2. 點擊超大按鈕「**📡 啟動極速 NFC 感應**」，建議開啟「**🔊 音效開**」與「**☀️ 強光高對比**」。
3. 選手晶片靠近手機背面感應區時：
   - **比對成功**：發出清脆提示音＋綠閃，大字體顯示編號、組別、姓名與經過時間（繞圈賽顯示「**第 N 圈 • XX.XX km**」）。
   - **防連點保護**：同一選手在防連點冷卻秒數內（預設 30 秒）重複靠近，發出警示音＋黃閃略過，不重複計時。
   - **未報名攔截**：若刷到「未報名本場活動」的晶片，立即紅燈警報攔截，避免混場誤計。
   - **晶片損壞備案**：直接使用下方「**⌨️ 手動補感應**」輸入參賽編號、姓名或身份證補登。
4. **無網路離線作業與統一上傳**：
   - 山區無訊號時手機會顯示「`無網路・離線暫存`」，照常感應計時，所有紀錄安全儲存在手機 IndexedDB（即使重新整理也不會遺失）。
   - 回到有網路區域後，點選作業區上方「**☁️ 統一上傳離線資料**」即可一次批次上傳雲端。
   - 若賽後現場仍完全無網，可點「**💾 匯出離線檔**」傳送 `.json` 給總部後台點「**➕ 合併離線備份檔**」彙整。

---

### 階段 5：賽後成績修正、報表匯出與公開查詢

1. **人工修正成績**：
   - **一般距離賽**：於後台「**🏆 成績管理與修正**」直接點擊任一選手的站點時間或罰時，即可編輯、補登或刪除並自動重算名次。
   - **繞圈計時賽**：點擊該選手右側「**🔁 逐圈明細 / 補刪圈**」，可檢視每圈耗時、補登漏感應的圈次或刪除誤刷圈，自動重算總里程與名次。
2. **匯出 Excel 報表（`.xlsx`）**：
   - 提供「**完整報表（主辦留存）**」與「**隱碼報表（對外公告）**」兩種版本，距離賽與繞圈賽會自動輸出專屬格式。
3. **公開即時查詢頁（`public.html`）**：
   - 於後台點「**🌐 複製本活動公開查詢連結**」，轉成 QR Code 張貼於會場，選手與親友免登入即可即時查詢動態、剩餘倒數與排名。

## 六、重要注意事項與常見問題排錯

### 1. 硬體與手機事前設定清單

| 檢查項目 | 注意事項 |
|---|---|
| **支援裝置與瀏覽器** | Web NFC **僅支援 Android 手機之 Google Chrome（v89 以上）**。<br>❌ 不可使用 iPhone (iOS Safari)、電腦瀏覽器，也**不可在 LINE / Facebook 內建瀏覽器中直接開啟**（請點選「以 Chrome 開啟」）。 |
| **建議採購 NFC 晶片** | 強烈建議採購 **NTAG213 / NTAG215 / NTAG216** 抗金屬貼紙或矽膠手環（支援標準 NDEF 讀寫）。若已採購唯讀卡或 MIFARE 卡，請改用系統內建的「**🔗 僅綁定晶片 UID**」。 |
| **Android 系統設定** | 1. 開啟手機「設定 → 連線裝置 → **NFC 開關**」。<br>2. 開啟「**自動設定日期與時間（網路校時）**」，確保所有站點手機時間一致。<br>3. 延長螢幕休眠時間並外接行動電源，避免待機切斷 NFC 感應。 |
| **建議加入主畫面** | 在 Chrome 選單點「**加到主畫面**」安裝為 PWA App，避免現場單手操作時誤觸瀏覽器返回鍵。 |
| **防連點秒數調整** | 一般路跑預設 `30 秒`；若為**繞圈計時賽**（例如單圈 2.54 公里最快也要 8 分鐘以上），建議於後台將該活動防連點秒數調高至 `60～120 秒`，避免選手在補給桌逗留重複觸發感應。 |

### 2. 常見異常排錯速查表

| 狀況 / 錯誤訊息 | 原因 | 解決方法 |
|---|---|---|
| 出現 `NotAllowedError` | Chrome 尚未允許此網站使用 NFC，或手機 NFC 沒開 | 點擊 Chrome 網址列左側圖示 → 權限 → 允許「NFC 裝置」，並確認系統 NFC 已開。 |
| 出現 `NotSupportedError` | 晶片為 MIFARE Classic、悠遊卡、唯讀鎖定或非 NDEF 卡 | 改點「**🔗 僅綁定晶片 UID**」免寫入直接綁定即可使用；或更換 NTAG213/215/216 晶片。 |
| 出現 `NetworkError` | 感應時晶片移開太快，或距離背蓋天線太遠 | 貼緊手機背面 NFC 天線位置並**保持靜止 1～2 秒**直到聽到成功提示音再移開。 |
| 手機看不到電腦新建的活動 | 尚未於 `js/config.js` 填入 GAS 網址，或電腦端還沒點同步 | 1. 確認電腦後台已點「🔄 一鍵完整雙向同步」。<br>2. 確認 `js/config.js` 已填入網址並上傳 GitHub（或在大廳點「🔗 綁定雲端網址」→「🔄 同步雲端資料」）。 |
| 更新 GitHub 後手機畫面仍是舊版 | 瀏覽器 Service Worker 仍保留舊版離線快取 | 在手機 Chrome **連續重新整理 2 次**，或關閉分頁重新開啟即可自動更新至最新版。 |
